# 自动移民、高迁、首占与加速实施教程

下列行为是本工具的实施约定。字段和嵌套结构直接使用 [核心字典](protocol-core.json)，读法见 [字典说明](protocol-schema.md)。[输入输出示例](examples.md) 给出具体请求和状态合并；不同版本只核对差异。编码前对象不是 HTTP JSON 接口。

共用前提：已选择并连接角色，时间模块提供固定单调截止点；点击立即执行则直接进入发送步骤。每个任务只读取开始时保存的参数快照。

## 一、自动移民

### 输入与准备

用户选择角色、目标王国、北京时间、请求间隔和最多提交次数。参考默认间隔 200ms、最多 3 次，次数包含首次，上限 100。账号列表用于切换，不扩展为批量并发。

任务开始前可读取目标详情与活动信息；到点直接提交，不新增实力、联盟或部队资格检查。

| 用途 | 参考编号 | 请求 | 响应线索 |
| --- | --- | --- | --- |
| 可迁入列表 | 15852 | 空 | code tag 0、list tag 1 |
| 目标详情 | 15853 | kid tag 0 | code tag 0、info tag 1 |
| 活动通知 | 15881 | 服务端推送 | info tag 0，活动时间与阶段 |
| 正式迁入 | 15858 | 目标 kid tag 0 | code tag 0 |

身份来自当前连接，15858 不重复填写角色 uid。迁入与高迁是不同操作。

### 调度与结果

流程：准备 → 等待目标时间 → 写出迁入 → 记录业务结果 → 必要时有限重提 → 结束发送。

| 参考码 | 参考含义/处理线索 |
| --- | --- |
| 0 | 成功，停止后续提交 |
| 12070、12071 | 阶段未开放，可按剩余次数和间隔重提 |
| 12073 | 一般阶段错误，停止 |
| 12054 | 名额满，停止 |
| 12044 | 正在移民，停止并显示该状态 |
| 12085 | 目标连接失败，结果待核实，不自动重提 |

上述为基线处理表，其他返回码停止并显示原码；不把本地化文本索引当协议码。

最小默认是不重叠提交：只在收到可重提结果后安排下一次，且不早于上次实际发送加间隔。如果用户需要“未返回也继续提交”，作为明确设置，按发送时刻推进，但仍受最多次数约束。

单次响应等待参考值 25 秒；停止发送后可再留 5 秒接收迟到结果。超时不作为可重提错误，保持结果未知。

取消只阻止还没发出的请求，不能撤销已经写出的迁入。停止发送后继续接收已发请求的结果；超时或断线记为未知，不自动重新开始整轮。

## 二、定点高迁

### 输入与选择路径

输入王国 ID、X/Y、北京时间，提供“立即高迁”和“到点高迁”。只使用高级迁城道具，参考道具 ID 为 610104。一次任务只提交一次，不购买、不套连发或自动重试。

先判断目标是否为城市当前王国，再判断是否为角色本国：

| 条件 | 参考请求 | 请求字段 | 响应差异 |
| --- | --- | --- | --- |
| 目标 = 城市当前王国 | 5604 req_world_move_city | point tag 0 | code tag 0、point tag 1 |
| 否则，目标 = 角色本国 | 5633 req_world_gohome_to_point | point tag 0 | **code tag 3** |
| 其他目标王国 | 5632 req_world_wormhole_jumping_to_point | kid tag 0、point tag 1 | code tag 0 |

point 内部 x/y 都为 integer，tag 分别为 0/1，字典已有声明。跨服是否允许由服务器决定，不能把这条路由解释成任意自由移民。

### 道具和状态

追踪道具 id/count/exData 的流向，区分本地回调上下文和线上字段。按客户端调用迁城请求，不额外添加未声明的 itemid 或通用背包使用。

发送后先显示“已发送”。响应成功或位置通知到达后更新城市所在王国和坐标。参考相关通知：5651 的 city_point、5656 的 point、5673 的 city_point/jump_kid。

跨服成功响应若没有坐标，可用这次已被接受的目标坐标更新本地显示，再由通知同步。普通地图目标缓存随城市上下文更新。未返回时保持未知，不提前显示已迁城。

## 三、定时出征与首占

### 3.1 目标与动作

用户填写王国、坐标，选择普通地图或实际进入的活动场景。普通地图目标查询参考为 5617，含 kid 与 point；普通出征为 5701，含 type、endpoint、formation、必要 extra，**没有 kid 字段**。

因此查询哪个王国，不等于出征包就能跨到哪个王国。实际发送使用当前连接的地图上下文，不给 5701 强加字段。

| 普通地图动作 | 参考 type |
| --- | --- |
| 驻扎/占空地 | 6 |
| 攻击城市 | 2 |
| 打野怪 | 3 |
| 采集资源 | 4 |
| 太阳城 | 20 |
| 炮台 | 21 |
| 小/中/大据点 | 13 / 15 / 17 |
| 联盟总部/旗帜 | 12 / 10 |

读取目标是为了取得动作需要的信息。例如打野怪需要 map_monster.id，传入 extra.monsterid；不能用外层地图对象 ID 代替。改坐标后之前的 monsterid 失效，应重新取得。对只需坐标的动作，不强加一次目标查询。

### 3.2 英雄、兵阶、容量和比例

最小方案使用手动设置：

- 三个英雄位置，可按名称选择，内部保存英雄 ID。
- 盾、矛、射分别选择兵阶。读取已训练且可用数量大于零的兵种，每类最高阶作为初始默认值。
- 参考兵力初始化/更新为 4001/4002；元数据的 soldier_type 和 lv 用于分类。已解锁兵阶不代表已有可用兵。
- 用户输入出征容量及三类比例，按相对权重计算。例如容量 100000、比例 5:2:3，得到 50000、20000、30000。
- 整数取整后的余数放到最后一个非零比例的兵种，使总和等于输入容量。
- 不按库存裁剪、不计算科技和英雄容量增益，不在刷新时覆盖用户已改的选择。

参考 soldier ID 有 soldier_type × 10000 + tier × 100 的构造规律，仍优先以当前元数据中实际 ID 为准。三种兵分开选择会改变发包的兵种 ID，不只是界面展示差别。

内部编队可用“英雄位置 → ID”“兵种 ID → 数量”表达。参考请求 formation 中 hero_id 和 soldier 使用 k/v 条目；嵌套字段的类型/tag 见核心字典的 formation_build 与 pair_int_int。不要把内部字典直接当线上 schema。

若用户另行要求游戏保存编组：读取服务器下发的编组，按客户端规则展开为具体英雄与兵数，再发送。它是另一种输入来源，不默认给手动方案增加完整编组容量推导。

### 3.3 发送与绑定行军

流程：整理目标和部队 → 到点写出 5701 → 收到成功响应中的 march_info 或匹配通知 → 取得真实 march id → 开始加速。

不能拿用户填写的“队伍槽位”猜行军 ID。即使加速设置为不等回包，首次出征仍要取得该次实际行军；这是加速请求的必要输入。

如使用通知补足行军信息，应按角色、场景和本次目标关联，不能随便选列表里的最新一队。拿不到行军 ID 时记录具体缺口，不能对其他行军误发加速。

## 四、连续加速

### 4.1 控件与执行含义

- 次数 1～100，默认 10。
- 最小请求间隔由用户设置并保存；参考初值 10ms，可设 0。
- 来源支持仅道具、仅钻石、道具优先。
- 每次完成实际写入后，至少留出设置的间隔再写下一条；不等单条加速的业务回包。
- 发送记录与服务器结果分别统计，不自动补发被拒绝次数。

这个保守的间隔定义满足“请求之间至少间隔”，也包含写出本身耗时。实现位置在实际发送流程，不能只让界面慢慢把任务放进队列。

### 4.2 二阶道具与钻石

普通二阶行军道具参考 ID 为 301901，效果 50%；霜龙集结对应二阶道具为 301951，不能混用。

普通加速参考请求 5703，字段为 id、itemid、owner；id 指实际行军。其他场景有自己的声明，是否传 owner 以其字段为准。

“钻石加速”的参考调用链路：

1. 2001 快捷购买，字段为 id（道具 ID）、count: 1、use: false。
2. 随后调用当前场景的行军加速请求。

界面上用户选择钻石，内部可能是购买后使用。不要仅按按钮文案假定存在“直接扣钻石的另一个加速协议”；此为本文基线的两条请求机制，升级时只核对该分支的变化。

原客户端 BuyAndUse 是购买成功回调后使用，不等待背包推送。本工具按用户要求连续写出，连购买返回也不等待，这是明确的调度差异。一次购买＋使用算一次逻辑加速，实际是两条请求，两条之间也必须留出间隔。购买和使用分别统计，不能将购买成功计为加速成功。

### 4.3 “道具优先”的最小安排

可在本轮开始时读取所选道具库存，先安排相应数量的道具使用，剩余次数安排钻石方式。例如库存 3、次数 5，来源为道具、道具、道具、钻石、钻石；这轮不根据失败回包临时重排，也不额外锁库存。

库存必须对应所选道具 ID、当前账号和场景。初始化前为未知；道具优先按 0 安排，即全部走钻石，但界面仍显示“未知”并明确此行为。只读一次来源快照，不随本轮回包重排。仅道具模式直接发设定次数的道具请求，完全不按库存改次数；仅钻石全部走购买＋使用。

初始化 1101/1301 与增减 1102/1302 的具体字段和状态处理见 examples.md；钻石资源 ID 为 101，add/del 是数量增减而不是覆盖余额。

### 4.4 返回码与计数

8671 的参考含义是操作过于频繁。最小请求间隔由用户设置，没有固定间隔必然通过的结论；APK 按钮防连点不能证明服务器限流阈值。

界面分别显示逻辑加速已发送、加速成功/拒绝/未返回和购买结果。例如一轮 5 次钻石加速可以有 10 条实际请求；购买成功不算行军加速成功。最终消耗与抵达以实际资源、行军状态和服务器结果为准。

制作顺序为“进入本人可用场次 → 从响应保存真实实例身份 → 读场景目标 → 构造本场景动作 → 取得行军/队列 → 使用本场景加速”。战场号不凭王国 ID 编造，也不是用户随填一个编号就能加入。

注意场景部队与路径不同：矿区参考编队只发英雄；峡谷移动使用已有战场队列和建筑路径，不能照搬普通新建出征。使用对应场景的字段和动作表，未实现或未实测的场景分别标明。以上高迁教程只覆盖普通地图迁城。
