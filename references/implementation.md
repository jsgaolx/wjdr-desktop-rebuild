# 从零实施：开发路线与模块约定

本教程默认目标为 Windows 独立联网桌面程序，功能为账号与 Token、自动移民、定点高迁、定时出征及连续加速。先做单账号单任务，账号列表用于保存与切换。技术栈可用 Python 桌面方案，也可用开发者熟悉的其他方案；协议行为与界面框架无关。

下文的方法名和数据名是建议的应用内部接口，线上字段以当前客户端协议声明为准。

## 一、先确定成品行为

| 功能 | 用户提供 | 程序准备 | 到点动作 |
| --- | --- | --- | --- |
| 自动移民 | 角色、目标王国、北京时间、间隔与最多次数 | 会话、目标资料、单调截止点 | 提交迁入，按结果与设置有限重提 |
| 定点高迁 | 角色、王国、X/Y、北京时间 | 城市所在王国、角色本国、迁城路由 | 道具高迁一次 |
| 定时出征 | 地图/场景、王国与坐标、动作、英雄、三类兵阶、容量与比例 | 必要目标标识、编队、截止点 | 发送出征，取得实际行军 ID |
| 连续加速 | 道具/钻石策略、次数、最小请求间隔 | 本轮来源安排、场景加速协议 | 对该行军连续发送，异步记录结果 |

三个任务都提供“立即执行”和“到点执行”；输入时间为北京时间，格式 YYYY-MM-DD HH:mm:ss.fff。毫秒控制本机发起请求，不能保证服务器同毫秒处理。

首占是“出征＋加速”的使用方式，没有保证占领成功的单独协议。普通出征不要求用户先选已存在队伍；行军 ID 由出征后服务器生成。

## 二、公共模块只做必要职责

| 模块 | 建议接口/输入输出 | 负责什么 |
| --- | --- | --- |
| 账号会话 | login、import_token、export_token → AccountSession | 正常 SDK 登录、会话复用、本地保存 |
| 角色连接 | list_roles → Role[]；connect(role) → Context | 角色选择、登录、当前王国和场景身份 |
| 通信 | send(kind, fields) → sequence；on_response/on_notify | 编码、长度帧、加密状态、实际写出、接收分发 |
| 时间 | now_beijing、deadline(target) | 校准 UTC、单调时钟映射、时间显示 |
| 任务 | prepare(spec)、run(prepared)、cancel(task_id) | 快照参数、等待到点、调度具体动作 |
| 界面/记录 | TaskEvent → 状态、日志、计数 | 接收事件并刷新控件，不阻塞收发线程 |

最小实现可以每个模块一个文件，不需要微服务、插件框架或数据库。

关键数据分别保存：

- AccountSession：账号 fpid、session_key、本地显示名；不把手机号当角色 ID。
- Role：角色 uid、本国 kid、名称。
- Context：当前连接、城市当前王国、城市坐标、场景、真实战场实例、收到的资源快照。
- TaskSpec：任务类型、角色、目标、输入时间、用户部队设置、加速设置。
- PreparedTask：参数快照、确定的请求类型和字段、单调截止点。开始后改表单不改变这份快照。
- SendRecord：任务、请求序号、操作、目标时间、实际发送时间、写出完成时间。
- ResultRecord：对应序号、业务码、结果状态；加速逻辑次数与实际请求条数分别统计。

## 三、按以下顺序制作

### 第 1 步：建立客户端证据清单

按 [资料教程](setup.md) 取得 APK，记录版本、渠道、SHA-256。整理四类证据：SDK 登录、游戏登录与收发、三项功能、兵种/道具元数据。

每个条目写“文件/类/函数或资源位置＋读取到的字段＋结论”。参考编号用于缩小搜索范围。产出协议笔记，保留后续开发需要的字段、来源与调用顺序。

### 第 2 步：把账号入口与角色连接做通

按 [登录教程](login-communication.md) 做短信登录、Token 导入、Token 复制/导出、本地会话保存，再做角色列表和连接/断开。

只有导入文本，界面显示“已导入”；收到角色加载成功后才显示“已连接”。不要让“离线演示”复用真实连接状态。业务任务接到同一个已建立的角色连接上。

### 第 3 步：完成通信公共部分

先实现帧缓冲、Sproto 编解码、请求序号、单读循环和推送分发，再接加密初始化。登录响应必须及时更新密钥状态，不能等整个接收缓冲解析完才初始化。

发送提供“写出即返回序号”和“等待某序号业务结果”两种使用方式。出征需要后者取得行军；连发加速使用前者，回包由接收循环异步处理。

### 第 4 步：完成统一时钟

按 [时钟教程](time-ui-delivery.md) 生成 UTC 与单调时钟锚点，显示北京时间。开始任务时固定截止点，等待逻辑不依赖界面定时器。

先接一个只生成本地 TaskEvent 的调度入口，明确标为本地调度；它只帮助连接界面与任务层，不能冒充游戏操作成功。是否运行该入口按用户要求。

### 第 5 步：依次接三项任务

按 [功能教程](actions.md) 接入：

1. 高迁：选择当前服/回本国/跨服路径，一次发送，异步展示结果。
2. 移民：提交目标 kid，按明确结果有限重提。
3. 出征：手动编队、目标动作、必要附加标识，取得实际行军。
4. 加速：绑定该行军，设置来源、次数和最小请求间隔，发送与回包分别统计。
5. 有活动战场需求时再做各场景适配，不把普通地图包直接换成战场编号。

### 第 6 步：连接界面、保存设置并交付

界面控件只产生 TaskSpec，后台运行并投递状态事件。保存不含凭据的任务设置；凭据独立保存在本地。打包时说明程序、配置和运行环境各自来源。

具体控件、事件、交付清单见 [时钟、界面与交付](time-ui-delivery.md)。用户要求不测试时，只做文件与说明的核对，报告“未运行”，不要补做游戏操作。

## 四、每一步怎样交接给下一个 AI

写明这四项就能继续推进：

1. 已完成的模块及文件位置。
2. 当前版本已确认的调用链、请求字段和响应字段。
3. 未确认内容及应该去哪里查，例如“找到 5633，但还缺响应 code 的 tag”。
4. 下一步具体工作，例如“把城市当前王国更新接到高迁路由，随后接按钮事件”。

缺少账号时可以完成资料分析、界面、数据转换、调度和通信实现；不能声称实际联网已成功。缺少某个动作的声明时可以继续其他动作，不能凭其他游戏或其他场景猜字段补齐。
